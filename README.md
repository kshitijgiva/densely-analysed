# cctv-analytics

Self-hosted CCTV analytics pipeline: person detection + tracking (YOLOv8 +
ByteTrack) → re-identification (OSNet) → age/gender demographics (MiVOLO) →
anomaly alerts with LLM-generated explanations (Ollama). Implements the
early milestones (M1-M3) of a larger design covering privacy-preserving
retention, zone/dwell-time tracking, a Postgres/TimescaleDB + FastAPI
storage layer, and a text-to-SQL chat interface (not yet built here).

## Prerequisites

- **Python 3.11** (recommended - torch/ultralytics wheels may not exist yet
  for newer Python versions on all platforms; 3.14 was tried and had issues).
- **git** (needed to `pip install` the `mivolo` package from source).
- **[Ollama](https://ollama.com)**, running locally, with a model pulled -
  only required for `alerts.py`'s plain-English explanations:
  ```bash
  ollama pull llama3
  ```
  (`alerts.py` still works without it - it falls back to a templated
  sentence instead of an LLM-written one.)
- A video file with people in it, placed at `data/raw/sample_video.mp4`
  (relative to the repo root). Not included in this repo.

## Setup

```bash
# from the repo root
py -3.11 -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS/Linux

pip install -r analytics_service/src/requirements.txt

# mivolo isn't on PyPI and its setup.py needs an older setuptools
# (newer setuptools dropped pkg_resources, which mivolo's build imports):
pip install "setuptools<81"
pip install --no-build-isolation "git+https://github.com/WildChlamydia/MiVOLO.git"

# installing mivolo pins ultralytics==8.1.0, which is too old for how newer
# PyTorch loads .pt checkpoints - bump it back up:
pip install -U ultralytics

mkdir -p data/raw
# place your test video at data/raw/sample_video.mp4
```

### Optional: official MiVOLO backend

`render_tracked_video.py --demographics-backend mivolo-official` uses the
official MiVOLO repo's own person+face detector and fused face+body model
(more accurate, ~250MB of extra checkpoints, requires a second heavier YOLO
model per demographics retry). Default backend (`mivolo-body`) doesn't need
this - skip it unless you want to compare.

```bash
mkdir -p analytics_service/src/weights/mivolo
cd analytics_service/src
python -c "import gdown; gdown.download('https://drive.google.com/uc?id=1CGNCkZQNj5WkP3rLpENWAOgrBQkUWRdw', 'weights/mivolo/yolov8x_person_face.pt', quiet=False)"
python -c "import gdown; gdown.download('https://drive.google.com/uc?id=11i8pKctxz3wVkDBlWKvhYIh7kpVFXSZ4', 'weights/mivolo/model_imdb_cross_person_4.24_99.46.pth.tar', quiet=False)"
```

## Running it

All commands below assume you're in `analytics_service/src/`.

**Validate detection/tracking/re-id (M1/M2) - console report only:**
```bash
python validate_pipeline.py --max-frames 300
```

**Render an annotated video with boxes, track IDs, re-id identities, and
demographics, plus a JSON metrics report:**
```bash
python render_tracked_video.py --max-frames 300
# --demographics-backend mivolo-official   to use the official backend instead
# --no-demographics                        to skip M3 and just check M1/M2
# --start-frame N --segment-label "name"   to sample a specific segment (for alerts.py's history)
```
Outputs go to `analytics_service/results/tracked_output.mp4` and
`tracked_output_metrics.json`, and the run is logged to
`analytics_service/results/metrics_history.db` (SQLite) unless you pass
`--no-history`.

**Check for anomalies against run history and get an LLM-written alert:**
```bash
python alerts.py --video-source ../../data/raw/sample_video.mp4
```
Needs at least 4 prior logged runs for the same video source to establish a
baseline - run `render_tracked_video.py` a few times first (e.g. with
different `--start-frame` values to sample different segments) if you get
"Need at least 4 logged runs".

## Project layout

- `analytics_service/src/` - the pipeline (detection, reid, demographics,
  identity state, alerts) and its `weights/` (gitignored, auto-downloaded).
- `analytics_service/results/` - gitignored output (videos, metrics,
  history DB) - all regenerated by running the scripts above.
- `api.py`, `db/`, `query_service/` - FastAPI + Postgres/ChromaDB layer
  (M4 in the design doc) - not yet implemented/wired up.
- `data/` - gitignored; put your input video(s) here.
